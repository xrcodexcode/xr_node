# JavaScript Mastery — Code-First Learning System

Welcome to the **JavaScript Mastery** curriculum! This course is designed to take you from absolute beginner to an advanced JavaScript developer capable of passing rigorous technical interviews and building complex applications.

## Course Philosophy

This curriculum is built on a **Code-First** philosophy: **20% Theory, 80% Practice**.
You cannot learn to code just by reading or watching videos. You learn by typing, breaking things, reading errors, and solving problems.

- **No Spoon-Feeding**: You will be given problems and hints. Answers are kept separate to force you to think.
- **Progressive Difficulty**: 🟢 Beginner → 🟡 Intermediate → 🔴 Advanced → 🔥 Challenge
- **Real-World Data**: We avoid abstract `foo`/`bar` examples. Instead, expect to work with realistic data such as students, shopping carts, API responses, and user profiles.
- **Modern Standards**: We teach modern ES6+ JavaScript by default while marking older patterns as legacy when they appear.

## How to Use This Course

Each level (folder) is a self-contained learning module. Inside each folder, you will find a consistent structure:

- `notes.md` — The 20% theory. Quick explanations, visual diagrams, and syntax breakdowns.
- `worksheet.md` — Your primary active learning hub (Predict the Output, Complete the Code, Write from scratch).
- `exercises.md` — Extra coding challenges for the topic.
- `solutions.md` — The answer key (check this ONLY after trying yourself).
- `cheat-sheet.md` — A quick-reference guide for syntax and rules.
- `recall.md` — Active recall questions to test your retention.

**Your Job:** Spend most of your time in `worksheet.md` and `exercises.md`.

## Recommended Daily Schedules

Choose a pace that fits your life. Consistency beats intensity.

- **30 Mins / Day**: 5m active recall, 5m quick reading (`notes.md`), 20m coding (`worksheet.md`).
- **60 Mins / Day**: 10m active recall, 10m theory, 40m coding and debugging.
- **2 Hours / Day**: 15m active recall, 15m theory, 1.5 hours coding (including an exercise or mini-project).
- **Intensive (4+ Hours / Day)**: Ideal for bootcamps. Mix all of the above + deep dives into `projects/` and `challenges/`.

## Learning Paths

### 🏃 Fast-Track Path (MUST KNOW)
If you are in a rush to start building web apps or React, complete these core levels first:
- **Levels 0 to 8**: Fundamentals, DOM, and Events.
- **Levels 13 and 14**: Asynchronous JavaScript and Fetch API.

### 🧗 Full Path
For true mastery and interview readiness, complete all **21 levels** in order, including advanced topics like Closures, Prototypes, and Performance.

## Progression Rules & Mastery Criteria

1. **Don't skip the basics**: Even if you think you know strings and arrays, do the worksheets.
2. **Type, don't copy-paste**: Muscle memory is real.
3. **Mastery Check**: You have "mastered" a level when you can complete Part C (Write from Scratch) of the worksheet without looking at the notes.

## Project Strategy

Projects bridge the gap between "knowing syntax" and "building software".
- Start with **Mini Projects** (Part G in worksheets).
- Move to **Mid-Level Projects** (in `projects/` folder) combining 3-4 topics (e.g., a Todo App using DOM + Arrays + Events).
- Finish with the **Final Capstone** — a fully structured, multi-file application.

## Revision Strategy

To fight the "forgetting curve", implement these three strategies:
1. **Quick Revision**: 5-minute review of `cheat-sheet.md` before starting a new session.
2. **Practice Revision**: 10-15 minutes of coding previously solved problems from memory.
3. **Delayed Revision**: Once a week, revisit `recall.md` from modules you completed 2-3 weeks ago.

## Debugging Mental Model

When your code breaks (and it will), follow this model:
1. **Read the Error**: Don't just reload. What line? What does the message say?
2. **Isolate**: Which specific function or line is causing the issue?
3. **Inspect**: Use `console.log()` or debugger to check variables *before* the crash.
4. **Hypothesize**: "I think `user` is undefined because the API hasn't responded yet."
5. **Test**: Fix it and run again.
