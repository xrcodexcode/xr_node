# Working Code Paradigm

## Claim

Demonstrable, functional technical proof ("working code") consistently prevails over executive reputation, brand prestige, or unverified promises in critical technology evaluations.

## Explanation

The Working Code Paradigm dictates that in high-stakes technological selection, verified execution and live performance supersede slide decks, executive pedigree, or brand hype. Buyers and evaluators facing technical debt or architectural crises prioritize working, scalable software over speculative roadmaps.

This principle decided the future of Apple Computer in December 1996 during the selection of a next-generation operating system to replace the failing System 7:
- **BeOS (Jean-Louis Gassée)**: Gassée arrived alone to pitch Apple leadership without slides, presentation materials, or live demonstration code. Relying on executive reputation and entitlement, Gassée demanded $300M for an incomplete operating system.
- **NeXTStep (Steve Jobs & Avie Tevanian)**: Jobs and chief software architect Avie Tevanian delivered a live demonstration of NeXTStep. They showed robust multi-tasking capabilities, running simultaneous video streams, 3D graphics rendering, and enterprise applications without crashing, while directly addressing technical questions from Apple CTO Ellen Hancock.

The contrast between working code and empty reputation led Apple to acquire NeXT for $400M, laying the software foundation for OS X, iOS, and Apple's ultimate market resurgence.
